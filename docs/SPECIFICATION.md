# 1. Архитектурный обзор

Приложение спроектировано по модульному принципу со слабой связанностью компонентов (Low Coupling) и высокой степенью зацепления внутри модулей (High Cohesion). В проекте активно применяется паттерн Dependency Injection (Внедрение зависимостей), где управляющий класс принимает готовые экземпляры инфраструктурных компонентов.

## Диаграмма потоков данных и управления

- **Точка входа (main.py)** инициализирует базовые подсистемы и выступает в роли композиционного корня (Composition Root).
- **Компонент бизнес-логики (GameState)** инкапсулирует состояние игры и управляет другими модулями на основе событий.
- **Инфраструктурные компоненты** (UI, Stats, WordManager, InputHandler, GameTimer) изолируют работу с графикой, диском, потоками и вводом.

# 2. Спецификация компонентов (src/)

## 2.1. Модуль управления состояниями (game_state.py)

Класс `GameState` управляет жизненным циклом игрового процесса и реализует конечный автомат (FSM).

**Конструктор:** `__init__(word_manager, stats, ui)`

**Ключевые свойства:**
- `state`: Текущее состояние игры (`"STARTING"`, `"PLAYING"`, `"RESTARTING"`, `"LEVEL_COMPLETE"`, `"GAME_OVER"`).
- `score`: Текущий счет игрока.
- `combo`: Текущий множитель очков.

**Основные методы:**
- `load_level_without_display(level_idx)`: Подгружает массив слов для указанного уровня.
- `handle_input(event)`: Делегирует обработку ввода классу `InputHandler` и проверяет корректность слова при нажатии клавиши подтверждения.
- `update(dt)`: Обновляет таймеры и счетчики состояний на основе дельты времени.
- `draw()`: Опрашивает текущее состояние и вызывает соответствующие методы рендеринга из класса `UI`.

## 2.2. Менеджер уровней (word_manager.py)

Класс `WordManager` отвечает за загрузку и валидацию игровых данных (слов).

**Конструктор:** `__init__(levels_folder="data/levels")`

**Основные методы:**
- `load_all_levels()`: Сканирует директорию на наличие файлов `.json`, парсит их и сортирует по имени файла.
- `create_default_levels()`: Генерирует базовые конфигурационные файлы, если целевая папка пуста.
- `get_level(index)`: Возвращает словарь с данными уровня по его индексу или `None`.
- `get_level_count()`: Возвращает общее количество доступных уровней.

## 2.3. Обработчик ввода (input_handler.py)

Класс `InputHandler` изолирует низкоуровневые события клавиатуры Pygame.

**Конструктор:** `__init__()`

**Основные методы:**
- `handle_event(event)`: Принимает событие `KEYDOWN`. Обрабатывает `K_BACKSPACE` (удаление символа) и `K_RETURN` (возврат накопленной строки и очистка буфера). Возвращает строку или `None`.
- `get_current_input()`: Возвращает текущее состояние буфера набора.

## 2.4. Модуль статистики и логирования (stats.py)

Класс `Stats` обеспечивает персистентность (сохранение) прогресса пользователя на диске.

**Конструктор:** `__init__(data_file="user_data/progress.json")`

**Основные методы:**
- `load()` / `save()`: Чтение и запись состояния сессии в формате JSON.
- `record_success(word)`: Логирует успешный ввод слова с добавлением временной метки.
- `record_fail(word)`: Логирует пропуск/ошибку слова.
- `get_accuracy()`: Вычисляет процент точности.

## 2.5. Игровой таймер (timer.py)

Класс `GameTimer` реализует асинхронный отсчет времени во избежание блокировки основного GUI-потока.

**Конструктор:** `__init__(duration, callback)`

**Особенности реализации:** Наследует или использует класс `threading.Thread`. По истечении времени (`remaining <= 0`) безопасно вызывает переданную функцию `callback`.

## 2.6. Графический интерфейс (ui.py)

Класс `UI` инкапсулирует методы вывода графики. Не содержит бизнес-логики, принимает исключительно примитивы (строки, числа, флаги) для рендеринга.

# 3. Математические алгоритмы и бизнес-правила

## 3.1. Расчет точности печати (Accuracy)

Точность рассчитывается как процентное соотношение успешных попыток ввода к общему числу зафиксированных попыток. Расчет производится по формуле:


`Accuracy = N_success / (N_success + N_fail) × 100%`


Где `N_success` — количество успешно введенных слов, а `N_fail` — количество проваленных по таймауту слов. Если общее количество попыток равно 0, точность принимается равной 100%.

## 3.2. Логика начисления очков (Scoring)

При успешном вводе слова итоговый прирост очков зависит от длины слова L и текущего модификатора комбо C:


`ΔScore = L × C × BasePoints`


- При успешном вводе: C = C + 1
- При таймауте или перезапуске: C = 1 (сброс комбо)

# 4. Спецификация форматов данных (JSON)

## 4.1. Конфигурация уровней (data/levels/level*.json)

Каждый файл уровня должен строго соответствовать следующей JSON-схеме:

```json
{
    "name": "Строка: Название уровня для отображения в UI",
    "words": [
        "массив",
        "строк",
        "для",
        "тестирования"
    ]
}
```

## 4.2. Файл прогресса пользователя (user_data/progress.json)

Файл обновляется автоматически при совершении каждого действия. Структура документа:
```json
{
    "successes": [
        {
            "word": "cat",
            "time": "2026-05-27 15:30:22.104231"
        }
    ],
    "fails": [
        {
            "word": "programming",
            "time": "2026-05-27 15:31:05.441290"
        }
    ],
    "final_score": 1450,
    "last_played": "2026-05-27 15:31:06.001924"
}
```

# 5. Среда выполнения и требования к инфраструктуре
## 5.1. Системные требования
Среда интерпретации: Python версии 3.12 или выше.

Ключевые зависимости: pygame==2.5.2, pytest==8.1.1.

5.2. Конфигурация Docker-контейнера
Для изоляции процессов тестирования проект снабжен инструкциями Docker.

Сборка образов: Осуществляется на базе легковесного дистрибутива python:3.12-slim с предварительной установкой нативных пакетов разработки libsdl2-dev для корректной компиляции колес Pygame внутри контейнера.

Монтирование директорий: Локальная папка проекта монтируется в директорию /app внутри контейнера в режиме rw для сквозного сохранения результатов тестов и кэша.
